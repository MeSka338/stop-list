# Stop List

Панель управления стоп-листом кухни: менеджер может фильтровать позиции по
цеху и статусу, временно останавливать продажи и возвращать позиции в меню.
Проект выполнен на Next.js App Router, TypeScript, TanStack Query, Zustand,
React Hook Form, Zod, Tailwind CSS и Framer Motion.

## Запуск локально

Требуется Node.js 24.21.0 (версия зафиксирована в `.nvmrc`).

```bash
nvm use
npm install
npm run dev
```

После запуска приложение доступно по адресу `http://localhost:3000`.

Дополнительные проверки:

```bash
npm run build
npm run lint
npm run format:check
```

## Архитектура

Проект организован по принципам Feature-Sliced Design:

- `src/app` — Next.js layout, страница, провайдеры и route handlers;
- `src/widgets` — сборка экрана стоп-листа из самостоятельных частей;
- `src/features` — фильтрация меню, постановка позиции в стоп-лист и снятие
  со стопа;
- `src/entities/menu-item` — модель позиции меню, схемы, запросы, query keys и
  серверное in-memory хранилище;
- `src/shared` — транспорт API, общие утилиты и переиспользуемые UI-компоненты.

Зависимости направлены сверху вниз: `app → widgets → features → entities →
shared`. Серверное состояние хранится только в TanStack Query, а Zustand
используется для локального UI-состояния панели и уведомлений. Запросы,
мутации и оптимистичные обновления вынесены из компонентов, поэтому UI не
зависит от деталей HTTP-транспорта. Одна Zod-схема формы применяется на
клиенте и повторно в route handler перед изменением данных.

## Граница сервера и клиента

`layout.tsx` и `page.tsx` остаются серверными компонентами. Интерактивный
виджет стоп-листа является клиентским: он читает URL-фильтры через Next.js
navigation hooks, загружает данные через TanStack Query и управляет формой и
оптимистичными мутациями. Route handlers в `src/app/api` выполняются на
сервере, валидируют входные данные и обращаются к in-memory хранилищу.

Фильтры записываются в query string (`shop` и `status`), поэтому сохраняются
после перезагрузки и корректно участвуют в истории браузера.

## Работа mock API

API добавляет искусственную задержку и периодически возвращает ошибку, чтобы
можно было проверить состояния загрузки, откат оптимистичного обновления и
уведомления. Данные живут в памяти процесса: после перезапуска dev-сервера
они возвращаются к исходному seed.
